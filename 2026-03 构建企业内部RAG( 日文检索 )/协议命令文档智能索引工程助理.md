# 协议/命令文档智能索引工程助理



> 适用对象：FAE / 软件工程师 / 测试工程师 / 项目工程师 / 新入职成员
>
> 不需要 AI 背景，不需要懂日文，不需要熟悉协议文件结构



## 一、这个 Agent 是干什么的？

### 一句话说明

当你只知道“想做什么”（例如：设定温度），但不知道用哪个 Command、在哪个文档、哪个点位时，这个 Agent 可以直接告诉你答案。

## 二、在没有 Agent 之前，你通常是怎么做的？（现状回顾）

以“设定温度”为例，传统做法通常是：

1. 猜测可能使用的 Command（如果不知道，就只能一个个试）
2. 在大量日文文件夹中查找 CommandFormat / FrameFormat
3. 打开多个 Word / PDF
4. 搜索日文关键词（如果关键词不对，可能完全搜不到）
5. 在 Frame 中确认 Byte / D / Bit
6. 再三确认是否找对文件版本

👉 整个过程高度依赖经验，非常耗时，也不适合新人。

## 三、有了 Agent 之后，你可以怎么做？（核心价值）

你只需要做一件事：



> 用自然语言描述你的工程意图



例如：

- “我需要获取设定温度的命令和点位”
- “哪个命令用于启动风机？”
- “是否有读取当前温度的状态命令？”

Agent 会自动：

- 在内部协议/命令文档中查找
- 理解中日文混合内容
- 给出可工程执行的结论

## 四、Agent 能回答什么类型的问题？✅

你可以放心问以下问题：

### ✅ 功能 → 命令 / 点位

- 设定温度用哪个命令？
- 启动 / 停止风机的 Command 是什么？
- 目标转速在哪个 D 位？

### ✅ 状态 / 反馈类

- 当前温度在哪个命令里读取？
- 运行状态是哪个 bit？

### ✅ 协议理解辅助

- cmd4C 里每个 D 的含义是什么？
- 这个 Command 是 Old Frame 还是 New Frame？

## 五、标准使用步骤（非常简单）

### Step 1：打开 Copilot

- Copilot Studio 中的专用 Agent
- 或 M365 Copilot App

### Step 2：直接描述你的需求（不需要任何专业术语）

✅ 推荐写法：



> 我需要获取“设定温度”的命令和点位。



✅ 也可以这样：



> 哪个命令用于设定目标温度？



❌ 不需要：

- 知道 cmd 名称
- 知道文件夹位置
- 知道日文原文

### Step 3：阅读 Agent 的结构化结果

Agent 会以固定工程格式返回结果，例如：

- Command ID
- Frame / Format
- 数据点位（D / Byte / Bit）
- 文档来源路径
- 日文原文 + 中文解释

👉 这些信息可以直接用于代码、测试或沟通。

## 六、如何理解 Agent 的回答内容？

### 1️⃣ Command

- 表示使用的协议命令（如 cmd4C）
- 不同功能通常对应不同 Command

### 2️⃣ Frame / Format

- 指该 Command 所属的 Frame 格式
- 用于区分 Old / New 版本

### 3️⃣ 数据点位

- D? / Byte ? / Bit ?
- 是你在代码或工具中真正要读写的位置

### 4️⃣ 文档来源

- 告诉你答案来自哪一份原始文档
- 方便人工复核或对外引用

## 七、如果 Agent 给出“候选项”，该怎么做？

有时文档中存在：

- 多个相似命令
- 不同版本差异

Agent 可能会返回：

- 多个候选 Command
- 并附带置信度或建议

✅ 正确做法是：

- 优先查看置信度最高的结果
- 如有疑问，结合实际机型 / 版本确认

👉 这比“完全找不到”要高效得多。

## 八、Agent 的能力边界（请注意）

为了保证工程准确性：

- Agent 不会编造不存在于文档中的信息
- 所有结论都必须可追溯到原始文档
- 如果文档中确实没有定义，Agent 会明确说明

## 九、典型使用场景总结

✅ 新人快速熟悉协议 ✅ FAE 快速响应客户问题 ✅ 软件/测试定位命令和点位 ✅ 减少反复“你去问某某”的人肉流程

## 十、一句话总结



> 这个 Agent 的作用，不是替代工程判断，而是把“翻文档 + 找命令”的重复劳动自动化，让工程师只关注“做什么”和“是否正确”。



如对结果有疑问，仍然可以基于 Agent 提供的文档路径进行人工确认。
