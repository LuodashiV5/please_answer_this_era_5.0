# 🧭 MD500E 变频器项目导航指南

欢迎加入 MD500E 项目！这是一个基于 TI C2000 系列 DSP 的工业变频器（VFD）控制系统。

## 📋 项目概览

**硬件平台**: TI TMS320F2803x / TMS320F2808 DSP
 **开发工具**: Code Composer Studio (CCS)
 **项目类型**: 嵌入式电机矢量控制系统
 **应用领域**: 工业变频器、电机驱动控制

## 🗺️ 工程目录结构解析




## 🏗️ 架构分层说明

### 第一层：硬件抽象层（05_public/）

- **职责**: 提供芯片寄存器定义、外设驱动接口
- 关键文件:
  - `DSP2803x_Device.h` - F28035 设备定义
  - `DSP280x_Device.h` - F2808 设备定义
  - `*.cmd` - 链接脚本（内存映射）
- **修改频率**: 极低（除非更换芯片型号）

### 第二层：系统初始化层（01_system/）

- **职责**: DSP 启动、时钟配置、中断向量表、主循环调度

- 关键文件:

  - [main.c](vscode-webview://1fg8ho9h7phjpntk7l4dumuondm6m0g8lj3njc2a3bmbti65ogrl/01_system/main.c) - 主函数入口，时间片调度
  - `mainInit_2803x.c` / `mainInit_2808.c` - 芯片初始化
  - `DSP280x_CodeStartBranch.asm` - 启动代码

- 时间片架构:

  ```
  0.5ms 周期: Main05msMotor()      // 电机快速控制
  2ms 周期:   Main2msMotorA/B/C/D() // 电机慢速任务
  0.5ms 周期: Main05msFunctionA/B/C/D() // 功能模块
  无等待:     Main0msFunction()     // 后台任务
  ```

### 第三层：电机控制层（02_motor/）

- **职责**: 电机控制算法核心（FOC、V/F、弱磁、保护）

- 关键模块

  :

  - **encoder/** - 编码器信号处理、速度计算
  - **pwm/** - SVPWM 算法、死区补偿
  - **vc/** - 矢量控制（永磁同步电机 PMSM）
  - **vf/** - V/F 开环控制（异步电机）
  - **main_public/** - 状态机、保护逻辑、电流变换

- 数据流向

  :

  

  ```
  ADC 采样 → 电流变换 → 控制算法 → SVPWM → PWM 输出
  ```

### 第四层：功能应用层（func/）

- **职责**: 人机交互、通信、参数管理、故障处理

- 关键模块

  :

  - `f_funcCode.c` - 功能码参数管理（核心配置）
  - `f_comm.c` - 串口通信（Modbus）
  - `f_canlink.c` - CAN 总线通信
  - `f_io.c` - 数字 I/O 处理
  - `f_menu.c` - 键盘面板交互
  - `f_error.c` - 故障诊断与记录
  - `f_eeprom.c` - 参数存储

## 🛠️ 常见开发任务 SOP

### 任务 1：新增一个功能码参数

**场景**: 需要添加一个用户可配置的参数（如"加速时间 2"）

**操作步骤**:

1. **定义参数结构** → 修改 `func/include/f_funcCode.h`
   - 在对应的结构体中添加新字段
2. **初始化默认值** → 修改 `func/src/f_funcCode.c`
   - 在初始化函数中设置默认值
3. **添加参数描述** → 修改 `func/src/f_funcCodeNEW.c`
   - 在功能码表中添加参数编号、范围、单位
4. **EEPROM 存储** → 修改 `func/src/f_eeprom.c`
   - 将参数加入存储/读取列表
5. **应用参数** → 修改对应的控制模块
   - 例如加速时间参数需要在 `02_motor/main_public/` 中使用

⚠️ **避坑指南**:

- 功能码编号不能与现有冲突
- 参数范围必须做边界检查
- EEPROM 存储区域有限，注意空间分配

### 任务 2：修改 PWM 频率

**场景**: 需要调整载波频率（如从 10kHz 改为 15kHz）

**操作步骤**:

1. **修改 PWM 周期寄存器** → [02_motor/pwm/MotorPWM.c](vscode-webview://1fg8ho9h7phjpntk7l4dumuondm6m0g8lj3njc2a3bmbti65ogrl/02_motor/pwm/MotorPWM.c)
   - 找到 `gPWM.gPWMPrd` 的计算公式
   - 根据 DSP 时钟频率重新计算周期值
2. **调整死区时间** → 同一文件
   - 死区时间需要与 PWM 周期匹配
3. **更新 ADC 采样触发** → [01_system/mainInit_*.c](vscode-webview://1fg8ho9h7phjpntk7l4dumuondm6m0g8lj3njc2a3bmbti65ogrl/01_system/mainInit_2803x.c)
   - ADC 采样通常由 PWM 触发，需要同步调整

⚠️ **避坑指南**:

- PWM 频率过高会增加开关损耗
- 死区时间不能小于 IGBT 的最小死区要求
- 修改后必须重新测试电流采样精度

### 任务 3：添加新的保护功能

**场景**: 需要增加一个过温保护逻辑

**操作步骤**:

1. **定义故障码** → [func/include/f_error.h](vscode-webview://1fg8ho9h7phjpntk7l4dumuondm6m0g8lj3njc2a3bmbti65ogrl/func/include/f_error.h)
   - 在故障枚举中添加新的错误代码
2. **实现检测逻辑** → [02_motor/main_public/MotorInvProtect.c](vscode-webview://1fg8ho9h7phjpntk7l4dumuondm6m0g8lj3njc2a3bmbti65ogrl/02_motor/main_public/MotorInvProtect.c)
   - 在保护函数中添加温度检测代码
3. **触发保护动作** → 同一文件
   - 调用 `SetErrorCode()` 设置故障
   - 调用 `DisableDrive()` 关闭驱动
4. **故障显示与记录** → [func/src/f_error.c](vscode-webview://1fg8ho9h7phjpntk7l4dumuondm6m0g8lj3njc2a3bmbti65ogrl/func/src/f_error.c)
   - 添加故障描述文本
   - 确保故障被记录到 EEPROM

⚠️ **避坑指南**:

- 保护逻辑必须在中断中快速执行
- 避免在保护函数中调用耗时操作
- 故障恢复条件要明确（自动/手动复位）

### 任务 4：调试电机控制参数

**场景**: 需要观察电流、速度等实时波形

**操作步骤**:

1. **配置示波器模块** → [func/src/f_osc.c](vscode-webview://1fg8ho9h7phjpntk7l4dumuondm6m0g8lj3njc2a3bmbti65ogrl/func/src/f_osc.c)
   - 选择要观察的变量（如 `gADC.Ia`, `gRotorSpeed.Speed`）
2. **启动数据采集** → 通过上位机或键盘面板
   - 触发示波器功能码
3. **通过串口上传数据** → [func/src/f_comm.c](vscode-webview://1fg8ho9h7phjpntk7l4dumuondm6m0g8lj3njc2a3bmbti65ogrl/func/src/f_comm.c)
   - 数据通过 Modbus 协议传输到 PC
4. **使用上位机软件分析** → 外部工具
   - 查看波形、FFT 分析等

⚠️ **避坑指南**:

- 示波器采样会占用 CPU 时间，不要长时间开启
- 采样频率不能超过控制周期
- 注意数据类型（定点数需要转换为浮点数显示）

## ⚠️ 新人常见错误

1. **跨层调用混乱**
   - ❌ 错误: 在 `func/` 中直接调用 `02_motor/` 的内部函数
   - ✅ 正确: 通过 `MotorDataExchange.h` 定义的接口访问
2. **中断函数耗时过长**
   - ❌ 错误: 在 PWM 中断中执行复杂计算或通信
   - ✅ 正确: 中断只做必要的采样和控制，其他放到主循环
3. **全局变量滥用**
   - ❌ 错误: 到处定义全局变量，没有 `extern` 声明
   - ✅ 正确: 在 `.c` 中定义，在 `.h` 中用 `extern` 声明
4. **定点数运算错误**
   - ❌ 错误: 直接对 IQ 格式数据进行整数运算
   - ✅ 正确: 使用 `IQmathLib.h` 提供的宏（如 `_IQmpy`, `_IQdiv`）
5. **忘记看门狗喂狗**
   - ❌ 错误: 添加耗时代码后忘记调用 `KickDog()`
   - ✅ 正确: 在主循环的 0.5ms 周期中已经自动喂狗
