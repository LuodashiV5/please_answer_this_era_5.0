> **实时预测靠小模型，理解与诊断靠 LLM**

## 二、架构分层详解（从左到右）

### 1️⃣ Maglev Bearing System（物理系统）

这是你**最熟的部分**：

**原始信号来源**

- 位移探头（X / Y / 多点）
- 线圈电流
- 控制输出（电压 / PWM）
- 转速
- 温度
- 状态机 / 告警位

✅ 关键点：

- **不改控制架构**
- 预测系统是“旁路监听”

---

### 2️⃣ Data Acquisition（数据采集层）

**位置**：MCU / DSP / FPGA / 工控机

**职责**

- 固定采样率采集（如 1 kHz）
- 时间对齐
- 环形缓冲（sliding window）

📌 工程建议：

- **不要原始全量上传**
- 本地先做降采样 / 聚合

---

### 3️⃣ Feature Extraction（特征提取）

这是**工程 + AI 的分水岭**，非常适合你主导。

**典型特征**

- 位移：RMS / 峰峰值 / 偏置漂移
- 频域：特定频带能量（共振 / 不稳定）
- 控制：饱和比例、限幅次数
- 关联：位移 ↔ 电流相关性

✅ 这些特征：

- MCU 就能算
- 可解释
- 对模型稳定性帮助极大

---

### 4️⃣ Drop Prediction Model（跌落预测模型）⭐

这是**唯一做“智能判断”的模型**

**推荐形态**

- LSTM / GRU
- 输入：时间窗特征序列
- 输出：
    - 跌落风险概率（0~1）
    - 或离散等级（Normal / Warning / Critical）

📌 部署建议：

- 训练：PC / 服务器（Python）
- 推理：MCU / SoC（ONNX / TFLite）
- 推理周期：10~50 ms

⚠️ 注意：

- **不参与控制闭环**
- 只提供“提前感知”

---

### 5️⃣ Levitation Drop Prediction System（系统决策层）

这是**工程接口层**

**可以做的事**

- 风险 > 阈值 → 预警
- 风险持续上升 → 降额 / 软停
- 记录“跌落前 N 秒数据”

✅ 这一层完全可以是：

- C 代码
- 状态机 + 阈值

---

### 6️⃣ LLM（真正的“智能专家”）🧠

这块**不跑在实时系统上**。

**LLM 输入**

- 当前预测结果
- 特征摘要
- 工况描述
- 历史相似案例

**LLM 输出**

- ✅ 跌落类型判断
- ✅ 可能根因
- ✅ 排查建议（给 FAE / 运维）

📌 典型输出示例：

> “当前模式与【低速启动 + X 向探头漂移】跌落高度相似，  
> 建议检查：
> 
> 1. X 通道偏置
> 2. 启动阶段限流参数”

---

### 7️⃣ User Interface（人机接口）

**对象**

- FAE
- 客户
- 内部调试人员

**形式**

- Web UI
- 工控屏
- 调试工具

✅ LLM 让 UI 从：

> “一堆曲线 + 告警码”  
> 升级为  
> “像专家在说话”
